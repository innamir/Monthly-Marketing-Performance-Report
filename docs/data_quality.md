# Data Quality

## Контекст

Перед побудовою Tableau-дашборду була проведена перевірка якості сирих таблиць у BigQuery:

- `hw-skelar.marketing_report.spend`
- `hw-skelar.marketing_report.users`

Мета цього етапу — переконатися, що дані придатні для подальшої агрегації, об’єднання таблиць і побудови дашборду.

## 1. Базовий профіль таблиць

| table_name | row_count | min_date | max_date |
|---|---:|---|---|
| spend | 9,960 | 2025-01-01 | 2026-05-13 |
| users | 212,388 | 2025-01-01 | 2026-05-13 |

Обидві таблиці покривають однаковий період: з `2025-01-01` по `2026-05-13`.

## 2. NULL та невалідні числові значення

| table_name | null_date | null_channel | null_geo | null_value | negative_value |
|---|---:|---:|---:|---:|---:|
| spend | 0 | 0 | 0 | 0 | 0 |
| users | 0 | 0 | 0 | 0 | 0 |

У ключових полях не знайдено пропущених значень.

Також не знайдено від’ємних значень у полях витрат і виручки.

## 3. Перевірка поля is_payer

| is_payer | user_count |
|---:|---:|
| 0 | 183,114 |
| 1 | 29,274 |

Поле `is_payer` містить лише валідні значення: `0` і `1`.

## 4. Перевірка дублікатів користувачів

| row_count | unique_user_count | duplicate_user_rows |
|---:|---:|---:|
| 212,388 | 212,388 | 0 |

Дублікатів за `id_user` не знайдено.

Кожен користувач присутній у таблиці `users` один раз.

## Висновок

Дані пройшли основні перевірки якості:

- діапазон дат збігається між таблицями `spend` і `users`;
- у ключових полях немає NULL-значень;
- немає від’ємних значень у витратах або виручці;
- поле `is_payer` містить тільки валідні значення;
- дублікати користувачів не знайдені;
- значення `channel`, `geo` і `device_os` відповідають структурі з умови домашнього завдання.

Дані готові до трансформації в BigQuery і подальшого використання в Tableau.
